# 1.05x large-workbook performance follow-up

This is a local macOS arm64 optimization measurement against the clean
`v1.0.9` release commit. The target is a 1.05x reduction in the measured
`bench_workbook` load/edit/durable-save/reload path; it is not a claim about
Excel, openpyxl, ClosedXML, or other operating systems.

## Changes

- Parse ASCII A1 references directly from borrowed bytes instead of allocating
  an uppercase `String` for every cell.
- Skip formula-map lookups when a loaded sheet has no formulas.
- Avoid rescanning worksheet XML for absent optional feature containers.
- Defer worksheet `codeName` loading until the opt-in event-dispatch path.
- Pack worksheet coordinates into one `u64` sort key for deterministic output.

## Results

The strict paired runs used the repository's large-workbook harness with four
pairs and the same generated fixture, output validation, and decompressed ZIP
member comparison for both binaries.

| Cells | Before p50 | After p50 | Speedup | Result |
|---:|---:|---:|---:|---|
| 100,000 | 119.719 ms | 112.899 ms | 1.060x | met |
| 400,000 | 385.191 ms | 358.777 ms | 1.074x | met |

The 1,000,000-cell fixture is four 250,000-cell sheets. Its two large output
packages caused the full ZIP-comparison harness to terminate before producing
a complete report under the local disk/memory conditions. A lightweight
交互単体 run (four before/after samples, no simultaneous package retention)
measured p50 values of 1,689.605 ms before and 1,558.799 ms after (1.084x).
This 1M result is supporting evidence only, not a replacement for the strict
paired ZIP-comparison gate.

The local build passed `cargo check --workspace --offline`; worksheet parsing,
populate, and event-dispatch regression tests passed. The changes remain an
unreleased performance follow-up after v1.0.9.

## Reproduction

```sh
python3 compat/benchmarks/large_workbook_speed.py \
  --before /path/to/v1.0.9/bench_workbook \
  --after target/release/examples/bench_workbook \
  --output /tmp/elixcee-performance-105.json \
  --pairs 4 --cases 100k 400k
```
